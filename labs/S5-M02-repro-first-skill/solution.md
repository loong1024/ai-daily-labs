# 复现优先的 Bug 修复流程

## 开始前
确认已拿到以下 4 项关键信息：完整报错与堆栈、触发步骤、期望行为与实际行为、运行环境。缺少任何一项，先向用户询问，不要猜。

## 步骤
1. **复现**：编写能稳定复现问题的最小失败测试，运行并确认它失败，且失败原因与报告一致。
2. **定位**：提出 1–3 个根因假设，用日志、断点或二分法逐一验证，记下支持结论的证据。
3. **修复**：只改与根因相关的最少代码；不得修改、删除或跳过既有测试（若确认测试本身有误，先说明理由并征得同意）。
4. **回归**：运行新测试和完整测试套件，全部通过后再汇报。

## 停止条件
- 同一问题连续 2 次修复无效：停止修改，回滚到修复前的状态，汇报已验证和已排除的假设，由用户决定下一步。
- 需要改动公共接口、数据库结构或新增依赖：先说明理由并征得同意。

## 汇报格式
- 根因（一句话）及证据
- 修改了哪些文件、为什么
- 新增的回归测试名称
- 运行的测试命令及结果摘要
