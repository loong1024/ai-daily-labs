# S2-M02 · 单一提示硬跑又慢又贵？四种工作流模式同题 10 样本基准测

> **所属章节**：Ch.5 自动化 AI 工作流 · 确定性 AI 工作流编排与无人值守自动化  
> **实验类型**：`github` 白盒 Python 工程基准测 | **预计耗时**：90 分钟

## 1. 场景与常见痛点

把大模型接入客服工单、内容审校等多步业务时，如果只靠一条“全能大提示词”硬跑，往往同时遭遇三座大山：

1. **指令过载漏约束**：提取诉求、判定权限、安抚情绪与合规红线全塞进一条大 Prompt，面对多段长投诉经常顾此失彼。
2. **大小事混用旗舰模型**：把“怎么开电子发票”与四段式疑难客诉一律喂给高价慢速模型，响应慢且账单翻倍；遇到缺上下文的模糊工单还容易瞎编操作步骤。
3. **自评改写无轮次上限**：加上“生成 → 评估 → 重写”循环后忘记写死迭代次数上限，一遇到苛刻或自相矛盾的样本就死循环空转烧钱。

## 2. 实验目标

基于统一计费与耗时埋点的 `BenchmarkTracker` 和 `llm()` 封装，在同一组 **10 条复合客服工单样本**（4 条常见咨询 + 3 条多段长投诉 + 3 条边界模糊件）上完成 **1 组单提示基线 + 4 种工作流模式** 的同题量化对照：

| 模式标识 | 对应工作流模式 | 核心工程要点 |
| :--- | :--- | :--- |
| `single_prompt` | 单一提示词基线 | 全走 `pro` 大模型单次直出，作为耗时、成本与合格率参照系 |
| `prompt_chain` | 提示词链 + 程序化关卡 | 先抽结构化大纲 → 代码关卡校验必填项（最多重试 **2 次**）→ 生成正文 |
| `routing` | 难度与意图路由 | 小模型 `mini` 分流常见咨询，长投诉升级 `pro`，模糊件走追问澄清兜底分支 |
| `parallel_vote` | 并行分段 + 三视角审校 | 长投诉分段并发提取（`max_workers=5`）；对退款承诺用 3 个视角并行投票，对比 `majority_vote` 与 `any_hit` |
| `evaluator_loop` | 评估-优化闭环 | 生成 → 按字数与要素清单打分提意见 → 定向改写，**硬编码最多 3 轮上限** |

## 3. 本目录文件说明

- `fixtures/tickets_10.json`：10 条真实感企业 SaaS 工单（`T01–T04` 常见咨询、`T05–T07` 多段长篇投诉含诱导违规赔付陷阱、`T08–T10` 缺信息边界模糊件）。
- `starter.py`：预置好 `BenchmarkTracker`、`llm()` 计费埋点与 `single_prompt` 基线的骨架脚本（其余 4 种模式留有典型缺陷与 TODO）。
- `solution.py`：零第三方硬依赖的完整五模式对照实现与 Markdown 报表生成器。
- `verify.py`：四维量化门禁验收脚本（含苛刻必败样本的防死循环压力测试）。

## 5. 动手步骤指引

1. **跑通基线看初始账单**：运行 `python3 starter.py` 查看 10 条样本在 `single_prompt` 下的合格率、模拟延迟与费用基线。
2. **实现提示词链与难度路由**：
   - 在 `run_prompt_chain()` 中先提取 JSON 诉求清单并通过程序化关卡校验（失败重试上限 `<= 2` 次，即总提取尝试不超过 3 次），再生成回复。
   - 在 `run_routing()` 中将常见咨询路由至 `mini` 模型，长篇投诉路由至 `pro` 模型，模糊件进入澄清追问兜底分支（严禁臆测已后台修改完成）。
3. **实现 5 并发分段提取与三视角合规投票**：
   - 在 `run_parallel_vote()` 中按段落拆分长投诉，使用 `ThreadPoolExecutor(max_workers=5)` 并行提炼诉求后汇总；
   - 从法务红线、财务 SLA、客服话术三个独立视角并行审查草稿是否含越权退款承诺，同时记录 `majority_vote`（`>=2/3`）与 `any_hit`（`>=1/3`）两种合并策略结果，对命中违规的草稿执行安全改写。
4. **实现带 3 轮硬上限的评估循环并出表**：
   - 在 `run_evaluator_loop()` 中将最大轮次强行钳制在 `min(max_rounds, 3)` 以内，根据评估器缺失项反馈迭代改写，最后重跑 `python3 starter.py` 输出五模式对照表。
