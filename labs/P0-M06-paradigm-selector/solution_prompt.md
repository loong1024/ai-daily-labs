# AI 技术选型决策演练工作单（Solution 标准参考实现）

## 一、技术架构师选型互评提示词模板

请你扮演一位务实克制的企业 AI 首席架构师，严格依据【由轻到重四阶选型决策尺】（L1 精调 Prompt → L2 外挂知识库 RAG → L3 编排工作流 Workflow → L4 自主 Agent + MCP 协议），对以下业务选型方案开展“反过度设计”互评审计：
1. 选型铁律校验：凡是单次上下文能装下的纯文本任务绝不上外部基建；凡依赖海量常更新私有文档的问答必须走 RAG 溯源防幻觉；凡流转顺序与字段规则固定的批处理工序必须锁定为确定性 Workflow；仅当任务路径无法预先写死、需边看外部反馈边动态调整策略时才启用 L4 Agent + MCP。
2. 逐题挑刺输出：请检查我对题 A～题 D 的首选层级是否最轻量够用，指出原业务部门提议中的过度工程化或选型错配风险，并重点追问我对“题 C 为何选固定工作流而非自由 Agent”的边界判断是否严密。
3. 落地底线审查：检查我的个人真实业务三行选型卡是否写清了最小必需数据源以及高风险动作前的人工复核点。

## 二、四道典型业务场景选型诊断

### 题 A：将八百字发版说明改写为三版社群通知
- **首选层级**：L1 精调 Prompt（零基建）
- **不选更重或错误方案的边界理由**：八百字发版原文完全可以一次性贴入单轮对话上下文，且改写三种社群语气不涉及任何私有库检索或外部系统写入；若按市场部原提议搭建多智能体博弈系统，只会白白增加数倍延迟与开发维护成本，纯属过度设计。

### 题 B：依据三百份历史合同与法务手册解答合规疑问
- **首选层级**：L2 外挂知识库 RAG（补私有记忆）
- **不选更重或错误方案的边界理由**：三百份历史合同与动态更新的法务手册远超单次手工粘贴上限，单靠 L1 改提示词极易遗漏细节甚至编造违规条款；而合规答疑属于“检索权威切片 + 附出处生成回答”的固定链路，无需上 L4 自由规划 Agent 增加不可控工具调用风险。

### 题 C：将新增工单按固定规则抽字段、翻译并写入表格
- **首选层级**：L3 编排工作流 Workflow（固化标准工序）
- **不选更重或错误方案的边界理由**：该场景“监听新工单 → 按固定五类规则抽结构化字段 → 翻译 → 追加写表”每一步先后顺序与字段格式完全确定，用 L3 固定工作流最稳妥；单靠 L1/L2 无法自动连接工单系统与在线表格，而若盲目上 L4 自主 Agent 反而可能出现跳步、漏写或误改历史表格数据的失控波动。

### 题 D：按模糊出差意图自主查日历、检索班次并汇总备选行程草案
- **首选层级**：L4 自主 Agent + MCP 协议（动态规划加标准手脚）
- **不选更重或错误方案的边界理由**：出差需求仅有模糊时间范围与避开周三董事会的约束，模型必须先调日历看哪两天真正空闲，若某天高铁或航班售罄还要动态回头换日期重新组合比对，执行路径无法用 L3 死板分支预先穷举；通过 MCP 协议标准化挂载日历与班次查询工具并停在“备选行程草案”交由人工拍板最为契合。

## 三、题 C 专项复盘：为何选固定工作流而非自由规划 Agent

题 C（新增售后工单抽字段、翻译并写入汇总表）是企业中最容易被误做成重型 Agent 的高频场景，必须选择 **L3 固定工作流（Workflow）** 而非自由规划 **Agent**，核心工程原因有三点：
1. **高确定性与零跳步保障**：工序链路固定为“触发读取 → JSON Schema 字段抽取 → 目标语种翻译 → 表格行追加”，每一步输入输出契约清晰；交给固定工作流可确保 100% 按序执行，而自由规划的 Agent 可能因提示词微小波动擅自省略翻译步骤或改写字段名。
2. **更低的 Token 成本与响应延迟**：Workflow 每条工单只需 1～2 次精准的小模型结构化调用即可秒级落表；若采用 ReAct 循环的自主 Agent，每处理一条普通工单都要多轮思考规划与工具试探，Token 消耗与耗时往往暴涨 3～5 倍。
3. **可观测排错与最小权限安全边界**：工作流哪个节点报错（如翻译超时或表格 API 限流）一目了然、支持单步重试，且只需授予工作流“追加一行”的最小写权限，彻底杜绝自由 Agent 误调删除或覆盖接口污染全表生产数据的风险。

## 四、MCP 标准扩展坞可接入工具与数据源盘点

MCP（Model Context Protocol）相当于大模型连接外部数字世界的“通用 USB-C 扩展坞”，一次封装即可跨主流客户端复用，常见可标准接入的工具与数据源包括：
1. **本地文件系统与代码仓库类（Filesystem / Git / GitHub MCP）**：让模型在授权目录范围内安全读取本地项目文档、检索历史代码变更提交与分支差异。
2. **关系型数据库与数据仓库类（PostgreSQL / SQLite / BigQuery MCP）**：支持模型先读取数据表 Schema 元数据，再在只读沙箱权限下执行受控 SQL 完成业务数据探查。
3. **日历日程与团队协作办公类（Google Calendar / Slack / Notion / 飞书连接器）**：支持模型查询成员忙闲档期、检索团队知识空间会议纪要或创建待确认的日程草稿。
4. **网页检索与浏览器自动化类（Search / Fetch / Playwright MCP）**：帮助模型实时抓取外部公开网页资讯、核验差旅班次动态并在受控测试页面完成交互验证。

## 五、个人真实业务三行轻量选型卡

- **业务痛点简述**：每周五需汇总本周 CRM 客户跟进记录与产品活跃度周报，自动筛选出活跃度环比下跌超 30% 的高优续费预警客户名单并生成客户经理提醒摘要。
- **首选方案层级**：L3 编排工作流 Workflow（固化标准工序：定时拉取周度指标 → 规则过滤跌幅超 30% 账户 → 调用模型提炼近三次跟进纪要摘要 → 写入预警看板；工序完全固定，拒绝盲目上 L4 自主 Agent）。
- **所需数据源与工具**：只读 CRM 跟进记录导出视图、客户周度活跃度统计表、企业内部看板消息推送 Webhook。
- **人工复核点**：工作流仅将预警摘要推送至客户成功经理内部看板，由人工核实客户是否因节假日停工导致正常低谷后，再人工决定是否发起客户关怀沟通，严禁系统自动向客户直接发送催促或续费邮件。
