## 一、场景痛点与实验目标

面对层出不穷的大模型技术名词，业务与研发团队在立项时极易掉进两类高昂误区：
- **杀鸡用牛刀（过度工程化）**：单靠优化一段 Prompt 就能解决的发版文案改写，或步骤完全固定的工单抽字段写表流水线，却盲目立项搞自由规划的多智能体（Agent），导致延迟翻倍、输出波动失控；
- **缺记忆硬磕提示词（方向选错）**：问答内容高度依赖经常更新的三百份内部法务合同与制度手册，却试图全塞进一段提示词，结果模型频频张冠李戴编造条款。

**本实验目标**：吃透 **“先试精调 Prompt → 缺私有资料补知识库 RAG → 固定工序走工作流 Workflow → 动态探路才上自主 Agent + MCP”** 的四阶由轻到重决策尺，独立完成 4 个典型业务场景的选型纠偏、MCP 标准扩展坞盘点与个人真实业务轻量选型卡设计。

## 四、核心标尺：AI 落地“由轻到重”四阶选型决策尺

1. **L1 · 精调 Prompt（零基建）**  
   单次对话上下文就能贴完所需背景资料，不涉及外部系统读写（例如：会议纪要提炼、单篇发版文案多风格改写）。
2. **L2 · 外挂知识库 RAG（补私有记忆）**  
   必须严格依据海量或频繁更新的内部制度手册、历史合同作答，要求有据可查、杜绝瞎编（例如：人事差旅政策答疑、法务合规条款检索问答）。
3. **L3 · 编排工作流 Workflow（固化标准工序）**  
   多步流转顺序与分支规则预先固定，追求高确定性、低成本与低出错率（例如：读取新增工单 → 按固定五类规则抽字段 → 翻译 → 写入汇总表）。
4. **L4 · 自主 Agent 配合 MCP 协议（动态规划加标准手脚）**  
   任务执行路径无法预先写死，需要模型边观察环境反馈边动态调整下一步动作；**MCP（Model Context Protocol）** 就像给大模型接入本地文件、数据库、日历与网页工具的“通用 USB-C 扩展坞”。

## 五、分步实操指引

1. **跑通红灯基线**：先运行 `verify.py`，看看 `starter_prompt.md` 中“万物皆上 Agent”的跟风方案踩中了哪些选型红灯。
2. **研读业务提案陷阱**：打开 `fixtures/business_cases.json`，查看题 A～题 D 四个部门各自的真实痛点与原提案误区，以及离线附带的 `mcp_catalog_snapshot` 工具分类说明。
3. **纠偏四道选型题**：在 `starter_prompt.md` 的 `## 二` 中为题 A、题 B、题 C、题 D 填入最轻量够用的 `首选层级`（L1～L4 一一对应），并用清晰的一句话写明**为什么拒绝更重或错误的方案**。
4. **深挖题 C 边界与盘点 MCP**：在 `## 三` 重点写清为何题 C（工单抽字段翻译写表）必须走固定 `Workflow` 而非自由规划 `Agent`（从确定性、成本延迟、排错可控性角度分析）；在 `## 四` 列举至少 3 类 MCP 可标准接入的外部数据源或工具。
5. **产出个人轻量选型卡**：结合你手头一项真实业务痛点，在 `## 五` 填好包含 `首选方案层级`、`所需数据源与工具`、`人工复核点` 的三行轻量选型卡，并升级 `## 一` 的架构师互评提示词，运行 `verify.py` 直至全绿通过！
