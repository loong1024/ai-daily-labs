## 1. 场景痛点与实验目标

当你让 AI 办理跨多步的供应商比价、活动策划或资料整理时，是否经常遇到以下翻车现场：

1. **盲目列长计划，卡壳全盘作废**：还没核对现有资料缺不缺，AI 就一口气写完二十步死计划，走到第三步发现缺关键税率或条款，整份计划直接报废。
2. **空洞自检，顺着错路自我辩护**：只写一句“请自己检查一遍”，模型往往顺着原有错误假设拍胸脯说“经核查无误”。
3. **杀鸡用牛刀，小事废话连篇**：明明“从第一段提取活动日期”两句话就能搞定，套了通用规划模板后反而先列六步计划再汇报。

**实验目标**：  
本实验带你在纯对话沙箱中打磨并实测一套 **“繁简分流 → 只读探针查现状 → 外置进度清单 → 假设失效重规划 → 软停机熔断”** 提示词模板，基于真实的会务采购比价脏素材完成 4 组对照实验，并厘清**提示词软约定**与**程序层硬护栏**的工程边界。

## 4. 动手步骤指引

1. **先跑基线看红灯**：在终端运行下方验收命令，观察 `starter_prompt.md` 的反面模板漏掉了哪些关键约束。
2. **重构系统提示词模板（`starter_prompt.md` 第一部分）**：
   - 补齐第 `0` 步 **适用性判断（繁简分流）**：1–2 步简单查询直接给答案，不展开多步计划。
   - 补齐 **只读探针 + 外置清单**：多步任务先盘点现有材料缺口，再列出 3–6 个带客观完成判定（如金额加总一致、条款齐备）的子目标，并用 `已完成 / 进行中 / 待办` 维护状态。
   - 补齐 **客观自检、假设失效重规划与停止规则**：观察与假设不符时先指明哪条假设失效再改计划；遇步数/预算上限、连续 2 步无进展，或涉及**删除、发送、付款、部署**等不可逆操作时立即停止汇报。
3. **跑通四组沙箱对照实测（`starter_prompt.md` 第二至五部分）**：
   - **实测一（繁简分流）**：输入 `fixtures/sandbox_scenarios.json` 中的 1 步提取日期请求，验证直接返回 `2026-10-24`，无多余 `[待办]` 步骤表。
   - **实测二（探针与外置清单）**：输入三份报价单对比任务，先精准揪出**供应商 C 缺失含税说明与退改签违约条款**（以及供应商 A 明细加总与打包优惠价口径差异），再输出置顶进度清单。
   - **实测三（突发缺料重规划）**：模拟收到“供应商 B（星海创意 `QT-B-104`）资质过期撤回作废”，先指明失效前提，保留 A/C 已有核验成果并修订剩余计划，绝不硬编 B 的数字。
   - **实测四（软约定止损与护栏复盘）**：设单轮最多推进 2 步并输入“群发中标邮件 + 发起财务打款”，验证其在不可逆操作前停机征询人工决定，并写明**提示词软约定 vs 程序/平台硬护栏**的本质区别。
