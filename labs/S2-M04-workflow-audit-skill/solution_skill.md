# 工作流可靠性审查

## 输入
- 工作流定义文件：{workflow_file}
- 流程用途，以及其中的不可逆动作（发送、付款、删除、发布）：{purpose}

## 审查步骤
1. **触发器**：列出所有触发器；检查条件是否过宽、流程写回是否会再次触发自己、定时触发的时区是否明确、Webhook 是否按事件 ID 或业务 ID 去重。
2. **数据流转**：分页是否取全；空值、缺字段、类型与时区转换是否显式处理；异常数据是否被记录而非静默丢弃。
3. **LLM 节点**：输出是否结构化并经过程序校验；分类是否有“其他/不确定”兜底；校验失败后是否有限次重试再转人工。
4. **错误处理**：是否区分可重试（429、5xx、超时）与不可重试（400、401）错误；是否使用带抖动的指数退避并设上限；有副作用的步骤是否幂等；重试耗尽后是否进入死信并告警。
5. **人工审批**：不可逆动作前是否有审批；超时策略是否为默认不执行（abort）；审批入口是否校验身份且只能生效一次（一次性令牌）。
6. **密钥与成本**：是否存在硬编码密钥；凭证权限是否最小、是否按流程隔离；日志能否追溯且已脱敏；是否设置调用次数与花费上限及告警；所有循环是否都有最大轮次。

## 输出格式
严格输出以下 Markdown 分级问题表（若无问题则填“无”）：

| 级别（BLOCKER/WARN/NIT） | 位置（文件:节点或字段路径） | 问题 | 建议修复 |
| :--- | :--- | :--- | :--- |

最后单独一行给出明确结论：**可上线** / **修复后上线** / **不可上线**，并列出上线前必须先修复的全部 `BLOCKER` 项。

## 约束
- **只读审查**：严禁修改任何文件、严禁运行工作流、严禁调用外部 API。
- **密钥脱敏铁律**：发现明文密钥或敏感凭证时，只报告所在节点与字段位置（或仅展示掩码占位），**严禁在输出报告中直接复述或回显任何明文密钥内容**。
- **零臆测**：不确定的平台默认行为一律标注“需人工确认”，不要臆测。
