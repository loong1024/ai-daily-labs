## 1. 场景痛点与实验目标

上线 AI 客服质检、内容审核或代码/合同风险筛查模块时，团队常陷入三大误区：
1. **肉眼抽查盲目乐观**：挑 3 条看 AI 说得头头是道就上线，结果真正致命的隐私泄露、私下转账、医疗夸大漏掉一大半。
2. **诱导挑刺导致误报爆炸**：提示词里写了「请严格审查并至少指出 2 处问题」，导致模型面对完全合规的客服回复也硬编毛病，人工复核被假警报淹没。
3. **缺少双硬指标标尺**：只算笼统的「总准确率」，说不清改完提示词后到底是检出变强了，还是误报变少了。

**实验目标**：基于现成的 **24 条正负配对评测集（12 条正常合规负样本 + 12 条植入隐蔽违规的正样本）**，输出结构化 JSON `{found_issue, reason}`，精确统计 **风险检出率（Recall）** 与 **正常样本误报率（FPR）**，用对照数据证明移除挑刺诱导语后的降噪效果。

## 4. 两个核心硬指标公式

| 指标 | 定义 | 公式 | 业务含义 |
| :--- | :--- | :--- | :--- |
| **定位检出率 (`Recall`)** | 12 条真违规正样本中，被准确揪出的比例 | `TP / (TP + FN)` | 越接近 `100%`，越不会放过致命合规与安全红线 |
| **干净误报率 (`FPR`)** | 12 条正常合规负样本中，被误判为有问题的比例 | `FP / (FP + TN)` | 越接近 `0%`，越不会瞎挑刺干扰正常业务 |

## 5. 动手步骤与验收命令

1. **查看基线问题**：运行验收脚本，观察诱导式提示词带来的高误报率以及解析/统计缺陷：
   ```bash
   python3 labs/S6-M07-precision-recall-eval/verify.py
   ```
2. **加固 JSON 解析容错 (`parse_judge_json`)**：兼容模型偶发输出的 ```` ```json ... ``` ```` 代码块包裹、前后说明文字及字符串布尔值，确保 100% 归一为 `{found_issue: bool, reason: str, parse_ok: bool}` 且绝不抛未捕获异常。
3. **补全评测指标计算 (`compute_eval_metrics`)**：精确统计 `tp, fn, fp, tn`、`recall`、`fpr`、`precision`、`valid_json_rate`、`total_latency_ms` 与 `estimated_cost_usd`。
4. **去诱导重写客观红线提示词 (`DEFAULT_SYSTEM_PROMPT`)**：删除「至少指出 2 处问题」等强迫挑刺语句，明确界定「必须拦截的实质违规红线」与「正常免责声明/合规婉拒不报警」，运行 `compare_prompts` 输出对照统计表。
5. **运行验收闭环**：
   ```bash
   # 验收你的当前实现
   python3 labs/S6-M07-precision-recall-eval/verify.py

   # 验证标准参考答案
   python3 labs/S6-M07-precision-recall-eval/verify.py --solution
   ```
