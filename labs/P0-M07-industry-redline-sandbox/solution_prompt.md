# 八大行业 AI 提效立项沙盘工作单（Solution 标准参考实现）

## 一、跨行业 AI 立项分拣提示词

请你扮演一位兼具商业敏锐度与风控底线的企业 AI 立项评审官，严格依据【任务四象限评估法】与【行业安全合规红线】，对各部门提交的 AI 提议逐条分拣为以下三档，并输出 JSON 或结构化评审表：

1. **四象限准入标尺（高频耗时 × 人类快速验真）**：
   - 优先评估子任务的“发生频率与节省工时”以及“人类在 1～3 分钟内对照一手事实核验对错的难易度”，拒绝不拆子任务就试图全自动替代整岗位的空泛立项。
2. **红黄绿三档分拣标准**：
   - `GREEN_QUICK_WIN`（高收益速赢区）：每周高频重复、输入事实源锁定（如核实过的 FAQ 库、实测参数表、定稿代码）、人工扫一眼或跑本地测试即可秒级验真，且无外部资损与泄密风险。
   - `YELLOW_NEED_HITL`（需人工把关受控区）：具备明确提炼或检索辅助价值，但涉及财务报销、法律合同条款或工业现场排障等低容错环节，必须配齐“原文页码溯源 + 确定性规则/脚本校验 + 持证专家/专员人工终审签字（HITL）”护栏后方可试点。
   - `RED_FORBIDDEN`（高危红线一票否决禁区）：凡命中以下任一红线，无论省多少工时一律驳回为 `RED_FORBIDDEN`：
     * **隐私与商业机密红线**：将未脱敏的员工薪资、身份证号、客户隐私或采购底价直接粘贴进免费公网大模型；
     * **零容错幻觉与法定资质红线**：在医疗领域跳过执业医师审核直接下诊断开具处方，或在法律诉讼中不查权威法规库直接让裸模型凭记忆默写判例案号与法条；
     * **物理产线与资金写权限红线**：拆除工厂硬件急停安全联锁让模型全自动停产线/带电重启，或无人工审批直接放开财务打款接口；
     * **大表心算错配红线**：把数百上千行精确财务薪资大表丢给概率生成模型做心算加总，替代确定性数据库或本地脚本。
3. **输出格式约束**：对每条提议依次输出 `id`、`bucket`（严格取 `GREEN_QUICK_WIN` / `YELLOW_NEED_HITL` / `RED_FORBIDDEN` 之一）、`risk_reason`（真实风险点诊断）与 `guardrail_action`（必需的人机核验护栏或降级改造建议）。

## 三、高危红线一票否决与降级改造卡

### 1. DP-07（诉讼法务判例辅助）合规降级改造
- **一票否决原因**：裸模型参数记忆不是精确法规数据库，凭记忆默写判例案号极易产出“形似神假”的幻觉案号，直接交法庭属于严重执业失范。
- **安全降级方案（改入 YELLOW_NEED_HITL）**：先由法务在官方权威裁判文书库检索下载真实判例全文，再将判例原文贴入受控上下文让模型提炼争议焦点与比对摘要，最后由执业律师逐字复核案号与法条有效性后签字定稿。

### 2. DP-08（互联网门诊问诊辅助）合规降级改造
- **一票否决原因**：胸痛发热可能涉及高危急症，模型无听诊检验能力且无法定处方权，直接自动开具抗菌与降压处方危及患者生命安全。
- **安全降级方案（改入 YELLOW_NEED_HITL）**：将 AI 严格限定在“院前症状时间线预采集 + 结构化病历草稿规整”，对药物过敏史缺失项强制高亮提醒追问，遇到胸痛急症关键词立即弹窗提示线下急诊，最终诊断与电子处方必须经执业医师面诊核准签字。

### 3. DP-09（HR 季度调薪核算）合规降级改造
- **一票否决原因**：将含真实姓名、身份证号与底薪的 800 行原表上传免费公网违反个人信息与商业保密铁律，且大模型心算长表必然出现漏行尾差。
- **安全降级方案（改入 GREEN_QUICK_WIN）**：数据绝对不出本地！HR 仅把表格列名表头、2 行虚拟脱敏假数据与调薪阶梯公式发给模型，让模型编写带边界校验的 Excel 公式或本地 Python 脚本，在本地电脑离线运行得出 100% 精确总额。

### 4. DP-10（车间反应釜异常处置）合规降级改造
- **一票否决原因**：拆除确定性硬件急停联锁并交由概率多模态模型直连 PLC 启停高压产线，一旦误触发将导致巨额停产损失或带电伤人事故。
- **安全降级方案（改入 YELLOW_NEED_HITL）**：100% 保留原有硬件急停安全联锁不变；AI 仅以只读方式接入传感器告警日志与设备手册知识库，在异常发生时向值班室大屏秒级推送历史相似故障排查卡，由现场持证班组长核实工况后手动拍板操作。
