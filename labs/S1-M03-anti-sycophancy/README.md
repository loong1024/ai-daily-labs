## 一、场景痛点：为什么拿业务立项问 AI，往往变成“给老板拍脑袋找借口”？

在企业新渠道投入、系统自研或重资产扩产等**重大业务立项评审**中，如果带着发起人的兴奋口吻直接问 AI，极易掉进大模型的**顺从吹捧（Sycophancy）**陷阱：

1. **半句定调带偏全局**：提问里只要漏出“竞品火出圈了”“这步棋太妙了吧”“请先表态支持再写立项书”，模型就会顺着长官意志猛吹市场红利，把重资产亏损隐患一笔带过。
2. **脉冲个案误当常态**：把单次头部大 V 联名的脉冲销量当成日常自播稳定产能，缺少财务与履约反方视角的交叉质询。
3. **先拍板后圆谎**：第一行先吐出“强烈支持立项”，后面整篇都在替这个轻率结论搜罗片面理由。

本实验带你用 **去倾向化 XML 隔离模板 + 蓝方/红方多立场独立盲写 + 红蓝交叉挑刺事前验尸**，逼出正反篇幅对称的硬核论据（每条限 2 句、总长限 800–1200 字内）、低成本最小验证实验（MVP）与可证伪的量化推翻条件。

## 四、四步实操指引

1. **去定调化 XML 填表（改造第一节）**：
   - 保留 `<context>`（业务背景）、`<proposal>`（中性立项议题）、`<facts>`（可核实经营约束）三段标签；
   - 对照 `fixtures/project_proposals.json` 中的 `proposal_01`，删光“火出圈了”“这步棋太妙了”“先表态全力支持”等诱导词，只填 1.2 亿营收结构、180 万预算占比、38% 毛利、650 元单台退货净损与日常自播 15 人在线等硬事实；
   - 明确要求蓝方与红方独立盲写、红蓝交叉挑刺，并写入“无新事实施压时坚持证据判断”“先分析后结论”铁律。
2. **蓝红等篇幅盲写与交叉挑刺（完善第二节）**：
   - 先列最多 5 条拍板前缺失的关键经营数据；
   - 分别从蓝方（业务增长）与红方（财务风控）列出最有力的 3 条理由，**每条不超过 2 句话，正反篇幅对称**，单轮正文控制在 800–1200 字以内；
   - 由红方交叉质询点破“单次达人脉冲幻觉”与“高客单大件退货净损 + 锂电广告合规封号”两大暗坑。
3. **设计低成本 MVP 与量化推翻条件**：
   - 不直接批 180 万建编，设计 3 万元级 14 天兼职主播最小赛马实验，并写明具体的量化推翻条件（如实测净 ROI ≥ 2.2 且 30 天退货率 ≤ 8% 即放行立项）。
4. **顺从吹捧偏见对照复盘（完善第三节）**：
   - 对比带风向提问 vs 独立红蓝盲测在篇幅占比、风险揭示度与抗主观施压上的显著差异。
