# S1-M05 · 长稿总结总漏后半段？分块贴便利贴与覆盖率核对实战

> **所属章节**：Ch.3 长文档与结构化 API · 长报告精读、模型 API 调用与批量表格抽取  
> **实验类型**：`idea`（零代码友好：`True`） | **专题**：`doc_data` | **预计耗时**：60 分钟

---

## 1. 场景痛点与实验目标

精读 50 页以上的行业内参、尽调报告或跨部门长会议纪要时，直接把全文一次性丢给 AI 总结会遇到三大硬伤：
1. **后半段注意力坍塌（Lost in the Middle / Tail）**：模型前半段写得头头是道，到了中后段悄悄偷懒，把压轴的违约金红线、仓储涨价和签字死线漏得一干二净。
2. **跨章节口径矛盾被擅自抹平**：第 3 节销售承诺“Q4 交付 6.5 万台”，第 7 节供应链实测“产能上限仅 4.8 万台”，一次性总结往往只抄前一个数或瞎取折中值，掩盖重大经营风险。
3. **漏段无感知、空段瞎凑数**：做完笔记根本不知道哪几块没被引用；或者遇到纯寒暄过渡段落时模型硬编结论凑字数。

**本实验目标**：
使用预处理好的带编号长报告（`[C01]`–`[C12]`），掌握零代码也能落地的 **Map（分块贴便利贴）→ 覆盖率审计表 → Reduce（保冲突按主题归并）** 闭环工作流，并与“一次性全文总结”同台对账找出后半段盲区。

> 💡 **零基础最快上手**：直接打开 `fixtures/long_report_chunks.md`，把两段结构化提示词依次粘进任意网页 AI 对话框，用表格核对 `[C01]`–`[C12]` 编号即可。

## 4. 动手步骤指引

1. **查看起点漏项诊断**：
   先运行 `python3 labs/S1-M05-mapreduce-coverage/verify.py`，查看一句话裸总结 `starter_prompt.md` 漏掉了哪些后半段靶子与覆盖率核对项。
2. **编写阶段一（Map 逐块贴便利贴）提示词与抽取表**：
   阅读 `fixtures/long_report_chunks.md`，设计固定表头提示词（`块编号 | 章节标题 | 核心结论与关键数字 | 风险/争议点 | 状态(有效/无相关内容)`），强制规定：**遇到茶歇寒暄/设备调试等无实质业务块（如 `[C04]`、`[C08]`）必须明确标为“无相关内容”并写明原因，严禁脑补凑数**。
3. **建立 `[C01]`–`[C12]` 覆盖率核对表**：
   逐行核查 12 个块编号：确认 10 个有效业务块全部在最终笔记中被引用，2 个过渡块明确登记为“无相关内容”，确保“既未引用也未标空”的遗漏块归零。
4. **编写阶段二（Reduce 归并保冲突）提示词并生成精读笔记**：
   按主题合并便利贴，每条结论末尾强制附带 `[Cxx]` 精确出处锚点（确保 `fixtures/golden_targets_and_oneshot_baseline.json` 中的 5 个黄金靶子 100% 命中可回查）；遇到 `[C03]`（销售承诺 6.5 万台）与 `[C07]`（供应链实测上限 4.8 万台）矛盾时，**严禁折中抹平，必须并列展示双方数字与 1.7 万台缺口**。
5. **输出“分块归并 vs 一次性总结”盲区对比清单**：
   对照 `fixtures/golden_targets_and_oneshot_baseline.json` 中的 `oneshot_summary`，逐条列出一次性总结漏掉的后半段细节（`[C09]`、`[C10]`、`[C12]`）及被掩盖的产能冲突。
