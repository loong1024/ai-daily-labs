## 一、场景痛点与实验目标

主流大模型起草的商务道歉函、对外公告与客户说明往往**排版工整、口吻笃定**，极易让人放松警惕：
- **事实盲信翻车**：被流畅行文迷惑，漏查模型顺手编造的可用率百分比、虚构法规条文或错误故障原因；
- **隐私脱敏裸奔**：习惯把含内部排障后台地址、测试密钥、其他客户实名手机号或采购底价的群聊记录原样带入上下文与初稿；
- **越权承诺与机械痕迹**：未清理模型擅自发挥的“免除下季度全部费用 / 十倍赔偿 / 100% 零故障”越权承诺，甚至带着未替换的 `【占位符】` 与多余 Markdown `**` 星号直接发给重要客户。

**本实验目标**：熟练运用 **《AI 初稿外发前 5 项人工签字核查单》**，对照一手权威事实底表，对一篇高风险客户致歉沟通初稿开展逐项排雷，揪出事实硬伤、隐私泄露、越权承诺与机械痕迹，最终产出一版可直接签字外发的干净终稿。

## 四、核心武器：AI 初稿外发前 5 项人工签字核查单

- `[ ]` **1. 事实与数字溯源核查**：文中所有百分比、日期、政策条文、产品参数与外部案例，是否均已回查一手权威信源逐字核对，确保零盲信模型记忆？
- `[ ]` **2. 保密与隐私脱敏核查**：输入上下文与输出正文中，是否已彻底清除未公开财务数据、客户真实姓名联系方式、内部系统地址及受保护商业秘密？
- `[ ]` **3. 权责与承诺边界核查**：文中是否夹带模型擅自发挥的过度承诺（如绝对化保障、未授权补偿方案、越权排期），发件人是否敢为每句话签字担责？
- `[ ]` **4. 逻辑闭环与受众匹配**：核心结论是否正面回应了客户或领导最关心的决策焦点，上下文因果推导与前后数字口径是否完全自洽？
- `[ ]` **5. 去机械味与格式清扫**：是否已删净未替换的`【占位符】`、多余的 Markdown 星号井号，并把生硬的排比套话润色为真诚自然的真人沟通语气？

## 五、分步实操指引

1. **跑一次红灯基线**：先运行下方验收命令，观察未排雷的 `starter_prompt.md` 触发了哪些安全与事实告警。
2. **对照底表标出雷区**：通读 `fixtures/ai_raw_draft.md`，对照 `fixtures/fact_and_policy_sheet.json` 把初稿中所有时间、数字、内部链接、客户隐私与赔偿表述逐一圈出。
3. **前 3 项硬核排雷**：在 `starter_prompt.md` 的 `## 三、初稿隐患排雷记录` 中列出至少 5 处具体隐患，并在终稿里删除虚构的光缆故障、`99.999%` 指标与虚构法规，彻底清除内部地址、测试凭证、其他客户实名电话与采购底价，将越权免单承诺替换为经审批的标准 SLA 抵扣方案。
4. **后 2 项精修润色**：统一恢复时间口径（`05:35` 恢复，`1,420` 笔队列订单零数据丢失、客户无需手动补单），清空所有 `【占位符】`、`**` 星号、`###` 井号与生硬套话，改写为诚恳自然的商务邮件正文，并升级 `## 一` 的受控起草提示词。
5. **逐条签字打钩并验绿**：确认 5 项核查复选框全部改为 `[x]`，再次运行 `verify.py` 直至 5 项指标全部 `PASS`。
