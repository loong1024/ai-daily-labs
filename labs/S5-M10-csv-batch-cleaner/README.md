# [S5-M10] 告别手工贴表：定制 CSV 与 Excel 合并清洗小工具

> **所属章节**：Ch.2 Vibe Coding 造物 · Vibe Coding 自然语言造物与 AI 协同开发  
> **实验类型**：`idea`（零代码实战沙盒包） | **零代码友好**：是 | **预计耗时**：20 分钟

## 1. 场景痛点与核心工程心法

周期性汇总各门店、直播间或合作渠道提交的几十份 CSV / Excel 分表时，职场人最常陷入两难：
- **手工复制粘贴**：遇到表头顺序打乱或同义词表头（如 `单号` vs `订单编号`、`来源渠道` vs `渠道名称`）极易整列错位，且难以排查跨表重复单号。
- **直接把原始业务表喂给大模型合并**：既存在敏感业务明细外泄风险，又常因上下文超限出现**静默漏行**或**凭空心算编造金额**。

**本实验核心心法**：**绝不让 AI 凭记忆心算原始表格，而是只给脱敏表头让 AI 生成确定性的本地批处理小工具，并用“行数守恒对账 + 脏数据小样本”做边界验收！**

## 2. 本目录实验资源说明

| 文件路径 | 说明 |
| :--- | :--- |
| `fixtures/store_east.csv` | 华东门店测试分表（5 行原始记录：含首尾空格、全空行、表内重复单号）。 |
| `fixtures/channel_live.csv` | 直播渠道测试分表（5 行原始记录：列顺序打乱、同义表头 `单号/来源渠道/实付金额`、跨表重复单号、非数字金额 `"待核实"`、全空行）。 |
| `fixtures/partner_south.csv` | 华南合作方测试分表（5 行原始记录：列顺序打乱、同义表头 `渠道/订单号`、缺失单号、非数字金额 `"N/A"`、跨表重复单号）。 |
| `starter_prompt.md` | **反面基线初稿**：采用“把表格贴给 AI 直接心算”的错误裸提问，且对账 JSON 漏算了跨表重复与异常记录。 |
| `solution_prompt.md` | **标准参考方案**：完整的三轮渐进脱敏造物提示词模板 + 基于 `fixtures/` 三份脏分表核算出的精确对账单与示范结果表。 |
| `verify.py` | **自动化红绿验收脚本**：实时读取 `fixtures/` 三份 CSV 执行确定性清洗核算，校验提示词关键约束与对账 JSON 标准答案是否分毫不差。 |

> **跨表去重顺序约定**：对 `fixtures/` 做样本对账时，统一按 `store_east.csv` → `channel_live.csv` → `partner_south.csv` 的导入顺序执行“按订单编号跨表去重（保留首条有效记录）”。

## 4. 实战步骤指引

1. **升级第一轮提示词（脱敏表头造工具）**：修改 `starter_prompt.md` 第一部分，明确要求大模型“不要心算表格，生成浏览器本地运行的单文件 HTML 批处理工具”，统一目标表头为 `日期, 渠道名称, 订单编号, 假设金额, 备注, 来源文件名`，写明单元格去首尾空格、同义表头映射（`来源渠道/渠道`→`渠道名称`、`单号/订单号`→`订单编号`、`实付金额`→`假设金额`）、过滤全空行、按 `订单编号` 跨表去重及带 UTF-8 BOM 头导出 CSV。
2. **补齐第二轮提示词（行数守恒对账 + 异常隔离）**：要求工具展示 `导入文件数`、`原始总行数`、`过滤空行数`、`异常隔离行数`、`去重剔除行数` 与 `最终有效行数`，校验守恒等式 `原始总行数 - 过滤空行数 - 异常隔离行数 - 去重剔除行数 = 最终有效行数`，并将缺失订单编号或假设金额非数字的记录单独隔离至《异常待复核清单》（标注来源文件名与原因）。
3. **核算 `fixtures/` 样本对账标准答案**：对照 3 份 CSV 样本（共 15 行原始数据），逐行核算出精确对账数值并填入 `starter_prompt.md` 的 ` ```json ` 对账区块。
4. **运行验收脚本闭环核验**：确认全部指标变绿后，即可用该提示词生成你专属的本地 `.html` 合表工具。
