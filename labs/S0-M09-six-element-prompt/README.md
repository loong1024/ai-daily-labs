# S0-M09 · 随口提问总拿套话？六要素+样板改写对照实验

> **所属章节**：Ch.1 提问与日常提效 · 结构化提问、写作润色与信息核实  
> **实验类型**：`prompt` ｜ **零代码友好**：是 ｜ **预计耗时**：15 分钟

## 1. 场景需求与常见痛点

日常写跨部门沟通消息、排期变更邮件或周报总结时，为什么 AI 写出来的稿子总要自己重写大半篇？

- **痛点 1**：只丢一句「帮我写封延期说明邮件」，拿到的全是「高度重视、全力以赴、通力协作、敬请谅解为盼」等生硬官腔和正确废话，关键日期和兜底安排一个没有。
- **痛点 2**：反复追加负向叮嘱「不要太啰嗦、不要像 AI 写的」，结果越改越干瘪，甚至漏掉必须让对方确认的关键动作。

**实验目标**：在完全相同的业务沟通任务上，并排对比**对照组 A（一句话裸问）**与**实验组 B（六要素正向约束 + 1 段个人历史行文样板）**，使 AI 直出初稿无需大段重写（手动微调字数 `< 20%`），精准复刻你平时的利落口吻。

> 💡 **免代码网页平替玩法**：直接打开日常使用的任一 AI 聊天框，新开两个独立会话分别输入 `Part 1` 的一句话裸问与 `Part 2` 的六要素+样板模板，15 分钟直观见证出稿质量跃升。

## 2. 「六要素 + 样板」结构化提问框架

| 要素编号 | 核心要素 | 本实验落地要点（以 `SCEN-01` 跨团队联调顺延为例） |
| :--- | :--- | :--- |
| **要素 1** | **沟通任务与文体** | 支付接口联调排期顺延说明消息 |
| **要素 2** | **读者与关系画像** | 合作方华东零售业务负责人周敏，沟通直接务实，不爱看长篇客套 |
| **要素 3** | **核心背景与硬事实** | ① 网关沙箱升级验签规则，核心接口已完成 85%，仅剩退款回调待补测；② 交付顺延至周五（11月20日）14:00 前，周三晚先开放查询与下单沙箱，不影响 11月25日正式灰度 |
| **要素 4** | **篇幅与结构正向约束** | 全文严格控制在 **180–240 字**，分**三短段**：结论先行 → 影响与补救 → 需对方确认的一件事（周五 14:00–16:00 预留 2 小时走查） |
| **要素 5** | **语气与禁用套话边界** | 每段第一句直接给核心信息，诚恳利落；严禁使用「赋能、抓手、高度重视、全力以赴、不言而喻、生态闭环、敬请谅解为盼、通力协作」 |
| **要素 6** | **个人历史行文样板** | 贴入 1 段自己真实写过的 ~100 字消息作为口吻示范（见 `fixtures/communication_scenarios.json`） |

## 5. 15 分钟实操步骤指引

1. **查看场景素材与裸问基线**：阅读 `fixtures/communication_scenarios.json` 中的 `SCEN-01` 事实卡、你平时的历史消息样板（`author_style_sample`），以及 `starter_prompt.md` `Part 1` 里一句话裸问产出的官腔废话。
2. **编写实验组 B 结构化提示词（完善 `Part 2`）**：把读者画像、硬事实、180–240 字三短段正向结构约束、禁用套话清单以及那段 100 多字的个人历史行文样板完整填入 `Part 2`。
3. **产出三短段成稿（完善 `Part 3`）**：用 `Part 2` 提示词生成实验组 B 直出初稿，确保分为**三短段**（空行分隔）、去空白总字数落在 **180–240 字**之间、每段首句直奔主题、零禁用官腔词且关键时间节点齐全。
4. **微调定稿并统计 A/B 删改率（完善 `Part 4`）**：在 `4.1 发前定稿` 中对 `Part 3` 做极少量顺口微调（验证微调字数占比 `< 20%`），并在 `4.2` 记录 A 组与 B 组的删改率对比及固定起手式沉淀。
