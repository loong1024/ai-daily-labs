## 1. 场景痛点与实验目标

在一线销售现场选型答疑与研发运维排障中，纯稠密向量检索经常在关键时刻掉链子：
1. **一字之差的近似型号分不清**：客户现场追问特种阀门 `GX-904B` 在高温强酸下的耐压上限，或工程师查 `HX-920B` 网关刷机方式，纯向量觉得 `GX-904A`、`HX-920A` 语义几乎一模一样，常把排在前面的错型号塞给大模型，险些报出错误耐压值酿成退货索赔；
2. **精确故障码被泛化稀释**：搜 `ERR-4091-LOCK` 分布式锁报错时，被同属超时话题的 `ERR-4090-NET` 常规重试指南挤下榜首；
3. **两路分数量纲冲突**：直接把向量余弦相似度（`0~1`）和 BM25 原始分（`0~几十`）硬相加，导致其中一路完全失效。

**本实验目标**：基于 `fixtures/eval_corpus.json` 内置的 **8 条跨场景真实切片（含近似故障码、A/B 近似硬件与防腐阀门参数表切片、口语化人事制度）与 4 组代表性评测问句**，亲手补全：
- **连字符代号保护 + 中文双字分词 BM25**（`bm25_rank`）：完整保留 `ERR-4091-LOCK`、`HX-920B`、`GX-904B` 词元并按 IDF 加权词频打分；
- **倒数排名融合（RRF）+ 交叉特征精排**（`rrf_hybrid_rerank`）：用 `1 / (60 + rank)` 绕开分制差异，叠加精确代号匹配精排，让精确型号与口语同义问句（“带薪休假留到明年春天”）双双稳居 Top-1（`MRR` 从 `0.62` 拉升至 `1.00`）。

## 2. 目录文件说明

- `fixtures/eval_corpus.json`：8 条知识切片（`D1`~`D8`，含 `ERR-4090-NET` vs `ERR-4091-LOCK`、`HX-920A` vs `HX-920B`、`GX-904A` vs `GX-904B` 跨页耐腐参数表切片及年假/病假制度）与 4 条黄金标注查询。
- `starter.py`：待补全基线（仅开启纯向量 `dense_rank`，被一字之差的近似型号干扰排错名次）。
- `solution.py`：零第三方依赖标准参考实现（含中文+型号词元切分、BM25 IDF 饱和度打分、RRF 双路融合与交叉特征精排）。
- `verify.py`：自动计算 `MRR` 增幅与精确型号 Top-1 命中率的红绿验收脚本。

## 4. 动手步骤指引

1. **跑基线看翻车（Red）**：运行 `python3 labs/S3-M04-hybrid-bm25-rerank/verify.py`，观察纯向量检索为什么把 `ERR-4090-NET`、`HX-920A`、`GX-904A` 排在目标切片前面（基线 `MRR = 0.62`）。
2. **实现代号保真分词与 BM25（`bm25_rank`）**：用正则提取完整连字符型号/报错码（统一大写），配合中文单字+双字切分计算 IDF 加权 BM25 得分，验证 `D2`、`D4`、`D6` 精准跃居第 1。
3. **打通 RRF 融合与交叉精排（`rrf_hybrid_rerank`）**：合并 `dense_rank` 与 `bm25_rank` 各自名次的 `1 / (60 + rank)` 得分，并对查询中出现的精确型号词元命中做精排加权，兼顾第 4 题口语同义问句（`D7`）。

> **免代码平替方案**：在 Dify 或 Cherry Studio 知识库设置中将检索模式从“纯向量”切为“混合检索 + Rerank（如 `bge-reranker-v2-m3`）”，粘贴 `fixtures/eval_corpus.json` 中的 `GX-904A/B` 切片当场对比召回排序变化。
